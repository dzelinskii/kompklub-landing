# Спецификация — Этап 1: промо-лендинг компьютерного клуба

Дата: 2026-07-13
Статус: черновик на согласовании

## 1. Контекст

Открывается компьютерный клуб в уличной / граффити-тематике. Владелец —
backend-разработчик (Python), во фронтенде не силён, знает React и немного
Next.js. Дизайном заниматься не хочет — визуальную часть собираем через
Claude Design, реализацию — через Claude Code.

Конечная цель — полноценный портал. Он разбит на этапы; данный документ
описывает **только Этап 1**. Остальные этапы перечислены в разделе 12 для
контекста и будут спроектированы отдельно.

## 2. Цель и границы Этапа 1

**Цель.** Один промо-лендинг, который умеет работать в двух режимах:
«скоро открытие» (тизер) и «уже работаем». К моменту запуска сайта клуб ещё
не открыт, но страница «работаем» должна быть готова заранее, чтобы в день
открытия переключить режим одним флагом без переделки.

**Концепция подачи.** Сайт оформлен как разрисованный граффити поезд.
Навигация не вертикальная, а дискретная «вагон за вагоном»: каждый экран —
отдельный вагон (раздел), переход к следующему выглядит как открывающаяся
раздвижная дверь вагона. Один шаг навигации = одна дверь = один вагон.
Граффити на поездах — корневой символ уличной культуры, поэтому концепция
попадает в тематику клуба. Дверь-навигация — прогрессивное улучшение поверх
обычного контента (см. раздел 6 и требование запасного режима в разделе 12).

**Входит в Этап 1:**

- Одностраничный сайт-поезд с дискретной навигацией «вагон за вагоном»,
  адаптивный (десктоп + мобайл), с запасным вертикальным режимом.
- Два режима отображения, управляемые одним флагом конфигурации.
- Форма предварительной регистрации, отправляющая контакт владельцу.
- Фирменный визуальный стиль (тёмная база + кислотно-зелёный акцент,
  граффити как фактура вагонов и дверей).

**НЕ входит в Этап 1 (осознанно, по принципу простоты):**

- Личный кабинет и авторизация.
- Онлайн-бронирование и оплата.
- Турнирная сетка.
- Меню бара с корзиной и заказом.
- Блог / новости.

## 3. Архитектура портала и место Этапа 1

Согласованная целевая архитектура всего портала:

```
[ Браузер ]
     │
[ Next.js (Vercel) ]     ← фронтенд + тонкий слой-прокси (BFF)
     │  REST / HTTP
[ Python / FastAPI ]     ← основной бэкенд: логика, интеграции, БД
     │
[ Gizmo Web API ] + другие приложения
```

Выбор фронта (Next.js) и языка бэка (Python) — независимые решения. Фронт и
бэк общаются по REST, поэтому Python сохраняется как основной бэкенд и
подходит лучше Node из-за нетривиальных интеграций (Gizmo и др.).

**Место Этапа 1.** У лендинга собственного бэкенда нет — это чистый фронтенд.
Единственное исключение — маленькая serverless-функция для приёма
предрегистраций (раздел 6). Фронт проектируется так, чтобы позже чисто
подключиться к Python-API: адрес API вынесен в переменную окружения, слой
запросов изолирован (заготовка делается сразу, даже если пока не используется).

**Заметка по Gizmo (для Этапа 2).** Gizmo Web API — это REST с HTTP Basic
авторизацией, поднимается локально на сервере клуба (порт по умолчанию 8080,
внутри сети клуба). Значит, Python-бэк должен иметь сетевой доступ к этой
машине (размещение на месте в клубе либо туннель). Решается на Этапе 2.

## 4. Технологический стек (Этап 1)

- **Фреймворк:** Next.js (App Router), React.
- **Хостинг:** Vercel (бесплатного тарифа достаточно для лендинга).
- **Язык:** TypeScript.
- **Рендеринг:** статическая генерация / серверный рендеринг страницы ради
  быстрой загрузки и корректной индексации поисковиками.
- **Стилизация:** на усмотрение этапа реализации; предпочтительно решение,
  дружелюбное к дизайн-токенам (цвета/шрифты), т.к. стиль приходит из
  Claude Design. Держать минимум зависимостей.
- **Предрегистрация:** Route Handler (serverless-функция) внутри того же
  проекта Next.js.

## 5. Два режима (тизер / работаем)

Один сайт, одно тело страницы. Режим задаётся флагом в конфигурации
(например, переменная окружения `SITE_MODE = "teaser" | "live"`).
Переключение режима не требует изменения кода и повторной вёрстки.

Различия между режимами локализованы в шапке и главном экране (раздел 6),
блок цен слегка адаптируется. Все остальные блоки — общие и готовятся сразу.

## 6. Структура: вагоны поезда

Разделы оформлены как вагоны поезда, идущие по порядку. Переход между вагонами
— открывающаяся раздвижная дверь. 🔀 — вагон меняется в зависимости от режима.

- **Оболочка-поезд (общая рамка).** Закреплённая шапка: логотип-заглушка ·
  индикатор-схема поезда (номера вагонов, текущий подсвечен) · главная кнопка
  справа. 🔀 Кнопка: тизер — «Предварительная регистрация»; работаем —
  «Забронировать». Оболочка отвечает за навигацию (скролл/стрелки/клавиатура/
  свайп), анимацию двери и запасной вертикальный режим.

- **Вагон 0 — Экстерьер / Hero.** 🔀
  - Тизер: разрисованный поезд ночью у платформы, «Скоро отправление», отсчёт
    до открытия на «табло станции», кнопка «Предварительная регистрация».
  - Работаем: «Посадка открыта», строка режима работы («открыто ежедневно …»),
    кнопка «Забронировать место».

- **Вагон 1 — О клубе.** Пара сильных фраз об атмосфере; 2–3 плитки-
  преимущества (топ-железо, периферия, атмосфера) как трафаретные наклейки.

- **Вагон 2 — Зоны.** Карточки: Стандартная PC-зона · VIP · Консоли (PS5/Xbox)
  · Приватная комната / буткемп · Бар. У каждой — описание, характеристика,
  фото. В режиме «работаем» допустимо «от N ₽/час».

- **Вагон 3 — Цены / тарифы.** 🔀
  - Работаем: тарифы «билетами» (день/ночь, пакеты часов).
  - Тизер: «тарифы скоро» либо анонс — по решению владельца.

- **Вагон 4 — Галерея.** Фото интерьера / уличного арта «в окнах вагона»
  (сейчас заглушки).

- **Вагон 5 — Как нас найти.** Адрес, часы работы, кнопка «Открыть в
  Яндекс.Картах» как табло конечной станции.

- **Вагон 6 — Контакты (хвостовой).** Telegram · VK · телефон · адрес + форма
  «Узнать об открытии» (Имя, Как связаться).

**Модель навигации.** Дискретно: один шаг = один вагон, вперёд/назад. Контент
всех вагонов присутствует в HTML по порядку следования (для SEO и запасного
режима). Анимация двери и «покадровое» перемещение — слой поверх. На мобильных
и при `prefers-reduced-motion` вагоны разворачиваются в обычные вертикальные
секции без агрессивной анимации.

## 7. Предварительная регистрация

Форма собирает контакт будущего гостя (минимум полей: имя + способ связи,
например Telegram-ник или телефон). Отправка идёт на Route Handler
(serverless-функцию) Next.js, которая пересылает заявку владельцу в Telegram
(через бота) или на почту.

Требования:

- Не хранить персональные данные в URL/параметрах.
- Явная обработка ошибок отправки: пользователь видит понятный результат
  (успех / ошибка), заявка не «теряется молча».
- Минимальная защита от спама (например, простая проверка/rate-limit) —
  детализируется на этапе плана.

Точный канал доставки (Telegram-бот или почта) и защита от спама — открытый
вопрос (раздел 11).

## 8. Визуальное направление (бриф для Claude Design)

Ключевой принцип — **сдержанность**: тёмная база + один фирменный акцент.
Референсы владельца передают вайб, но «слишком пёстро»; лечится
ограничением палитры.

- **Фон:** почти чёрный / асфальт, лёгкая бетонная фактура и зерно.
- **Фирменный акцент:** кислотно-зелёный. Трактовка — матовая уличная краска
  (трафарет, подтёки), свечение (glow) дозированно, только на ключевых
  кнопках и ховерах. Не превращать в сплошной неон.
- **Граффити — точечно:** теги, подтёки, трафарет как спот-акценты и
  разделители блоков, а не сплошной фон.
- **Типографика:** крупный «уличный» дисплейный шрифт для заголовков + чистый
  гротеск для основного текста. Граффити-шрифт в основном тексте не
  использовать (читаемость).
- **Детали:** мотивы стикеров/скотча, трафаретные края, «баллончик».
- **Тон:** «это своя тусовка», отстройка от светлых «добрых» сайтов.

## 9. Контент и заглушки

На момент разработки реального контента почти нет — используем заглушки,
заменяемые позже:

- **Название клуба** — отсутствует. В макетах логотип-заглушка «[LOGO]» в
  стилистике тега. Подставляется позже без переделки.
- **Цены** — заглушки.
- **Фото интерьера** — заглушки.
- **Адрес, часы работы, дата открытия** — заглушки / уточняются.
- **Контакты (Telegram, VK, телефон, ссылка на Яндекс.Карты)** —
  подставляются владельцем.

## 10. Рабочий процесс дизайна

1. Данный бриф (раздел 8) и структура (раздел 6) передаются в Claude Design.
2. В Claude Design собираются и крутятся макеты (тёмная база, кислотно-зелёный,
   баланс свечения подбирается глазами).
3. Готовый дизайн передаётся handoff-бандлом обратно в Claude Code.
4. Claude Code реализует лендинг на согласованном стеке.

## 12. Нефункциональные требования

- **Адаптивность:** корректная работа на мобильных и десктопе.
- **Производительность:** быстрая загрузка (лендинг, статика); анимация двери
  не должна тормозить слабые устройства.
- **SEO:** весь контент вагонов присутствует в HTML по порядку следования
  (серверный рендеринг/статика), навигация-поезд — слой поверх.
- **Доступность и запасной режим:** дверь-навигация — прогрессивное улучшение.
  На мобильных и при `prefers-reduced-motion` вагоны разворачиваются в обычные
  вертикальные секции. Переход между вагонами доступен с клавиатуры, при
  переходе фокус уходит в открытый вагон; контраст текста на тёмном/граффити
  фоне читаем; формы клавиатурно доступны.
- **Язык интерфейса:** русский.
